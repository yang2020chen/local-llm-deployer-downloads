# 双端 AI 协作开发｜视频配套资料包 V1

> 玩客笔记 · EP07：《我让两个 AI 开发软件，结果发现：写代码只是最简单的一步》
>
> 版本：1.0 · 整理日期：2026-10-19 · **文档包，非 Windows 安装程序**

这是一套可复制的**人工审批型** AI 协作方法：由 ChatGPT 帮你拆解任务并复核证据，由 GitHub Issue 保存任务和结果，由 Antigravity、Codex 或其他本地 Agent 在实际项目中执行。**不是让两个 AI 自动互相聊天、无人监管地发布软件。**

## 你能拿到什么

| 文件 | 用途 |
| --- | --- |
| `README.md` | 了解协作方法、准备环境、快速开始和软件下载入口 |
| `AGENTS-template.md` | 可复制、可按项目裁剪的双端协作规则，依据实际使用的 V1.4 协议整理 |
| `TASK-template.md` | Issue 任务规范、执行指令、审核指令及反馈示例 |
| `CASE-STUDY.md` | 根据三个真实开发事件整理的复盘，以及证据可信度说明 |

## 工作流：最小闭环

```text
你提出目标并明确授权
       ↓
ChatGPT 规划：目标 / 范围 / 验收 / 禁止事项
       ↓
GitHub Issue：冻结本次任务的边界
       ↓
你主动通知本地 Agent 执行指定 Issue
       ↓
本地 Agent：读协议 → 开发/检查 → 最小测试 → PR 与 Issue 回报
       ↓
ChatGPT：查看可取得的差异与证据 → PASS / FIX / BLOCKED
       ↓
需要时由你批准一次定点修正；合并、打包、公开发布另行审批
```

**三个底线**：① 没有用户授权不执行敏感操作；② 没有实际证据不报 PASS；③ 本次验收满足就停止，不顺手新增功能。

## 五步快速开始

1. **准备账号和项目**：GitHub 账号、目标代码仓库、本地 Agent（Antigravity / Codex 等），以及能正常使用的 ChatGPT。GitHub 接入能力取决于你实际启用的工具与权限；没有连接时可手工复制任务和审核材料。
2. **建立交接位置**：在你控制的 GitHub 仓库放入 `AGENTS.md`（以 `AGENTS-template.md` 为基础）。建议用独立的 Issue 仓库，也可与项目共用。私有项目请保持私有。
3. **定义单一任务**：照 `TASK-template.md` 写一个 Issue；把目标、允许修改的路径、验收证据、禁止事项一次讲清楚。
4. **人工启动本地执行**：在本地 Agent 中明确指定协议、仓库、Issue 编号。Agent 应先检查实际系统与项目版本；只做范围内工作，回传 PR/日志/检查结果。
5. **审核和收工**：将 Issue/PR 的可访问内容交由 ChatGPT 复核。审核结论可以是 `PASS`、`FIX`、`BLOCKED`；除非你单独批准，否则不得自动合并 PR、打包安装器或公开发布。

第一次练习可用**不涉及发布和外部凭据**的小任务，例如修复一个已经有明确重现步骤的界面错误。切勿直接给 Agent 无限制的系统权限。

## 一份值得照搬的任务原则

- **一条 Issue 只做一件事**。发现新优化点先记录 `OUT_OF_SCOPE`，而不是临时追加。
- **阶段分开**。代码审核通过 ≠ 安装包通过 ≠ 私有 Release 完成 ≠ 普通观众可以下载。
- **本地测试要有边界**。Cloud Reviewer 可以看 PR 和报告，但不应把本地 Agent 的 Windows 实测说成自己亲手执行。
- **把发布权留给人**。本地 Agent 写完代码、测试全部通过，也不自动获得合并、上传和公开权限。
