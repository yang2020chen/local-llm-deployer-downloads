# 双端 AI 协作｜任务与提示词模板

> 实用复制版。先替换 `OWNER/WORK-QUEUE`、`OWNER/TARGET-PROJECT`、`#12`、文件路径等占位符。不要直接执行示范任务。

## 1. 创建 GitHub Issue 前的五项检查

| 检查 | 你应能回答的问题 |
| --- | --- |
| 目标 | 本次只有一个明确目标吗？ |
| 范围 | 允许修改哪些文件？明确不改什么？ |
| 验收 | 能用实际文件、测试、日志或截图判断成败吗？ |
| 权限与停止 | 哪些操作需要单独授权？失败后怎么办？ |
| 无夹带 | 有没有顺手添加未经批准的新功能？ |

## 2. GitHub Issue 正文（直接复制）

```yaml
v: 1
kind: code
target: OWNER/TARGET-PROJECT
goal: "修复设置页点击保存后没有成功提示的问题"
scope: "仅限 src/ui/settings/ 与直接相关的最小测试"
accept: "保存成功时显示提示；失败时显示安全错误；相关测试通过，提供最小验证证据"
limits: "不修改配置格式、不重构无关模块、不自动合并、不得公开发布"
```

如果使用 `docs` 或 `data` 类型，把 `kind` 改为对应值，并为该类型写可验证的验收标准。`target` 指向**实际存在且你有权限的仓库或工作区**，不要让 Agent 猜。

## 3. 给 ChatGPT：规划任务的提示词

```text
你负责规划与审核，不直接代替本地 Agent 执行。
请根据我的目标，为 OWNER/WORK-QUEUE 生成一条可审查的 GitHub Issue。

目标：[填写目标]
目标项目：[填写仓库/工作区]
允许修改：[填写范围]
必须验收：[填写真实可验证的结果]
禁止事项：[填写不允许的行为]

先做目标、范围、验收、权限与停止条件、范围纯度这五项预审。
只输出一条 Issue 的标题与正文（首个代码块使用 v: 1 YAML）。
不要添加未要求的功能。缺少必需信息时只指出最小缺口。
```

> 没有已连接的 GitHub 写入权限时，请手动将输出复制到 GitHub Issue，不要认为文字已经自动创建任务。

## 4. 给本地 Agent：启动执行

```text
请先读取 OWNER/WORK-QUEUE 仓库 AGENTS.md，然后读取 Issue #12。
在当前机器实查 OS、Shell、目标项目、分支、工作区差异和所需工具权限。
核对 Issue 中 goal、scope、accept、limits 后执行，仅修改允许范围。

需要扩大范围、缺少授权或无法满足验收时立即 BLOCKED，回传最小阻断原因。
只运行必要的最小验证；没有运行的检查写 not_run。
完成后在原 Issue #12 回传变更链接、真实检查结果及脱敏证据。
不得擅自合并 PR、制作安装包、上传或公开发布。回传后停止。
```

## 5. 本地执行回报（示例，不是实测结果）

```yaml
task: 12
status: PASS
changed: https://github.com/OWNER/TARGET-PROJECT/pull/3
checks:
  - "单元测试：在本地实际执行、通过；详情见提交记录"
  - "设置页手工操作：实际执行、成功提示出现"
  - "跨平台验证：not_run（本轮仅授权当前系统）"
evidence: "PR #3；已脱敏的截图路径；commit SHA"
blocker: none
```

请用实际执行情况替换示例，不要直接复制其中的 PASS。

## 6. 给 ChatGPT：审核任务

```text
请审核 OWNER/WORK-QUEUE Issue #12 与其关联 PR。
先读 AGENTS.md 与 Issue 原始验收要求，然后核对可访问的代码差异和证据。
把“你实际读取/验证过的”与“本地 Agent 回报的”分开。
只给 PASS、FIX 或 BLOCKED 中的一个结论，明确阶段与理由。
若需 FIX，仅列原范围内最小修复；若范围外或权限不足则 BLOCKED。
不创建新需求，不自动合并、不打包、不公开发布。
```

## 7. 范围内定点修正提示词

```text
本次只修复审核列明的以下原范围缺陷：[逐条列出]。
不处理其它问题；其它发现仅记 OUT_OF_SCOPE。
保留原 PR，修复完成后执行必要的局部检查、回传新的 commit SHA 与证据。
通过即停止；仍阻断则说明缺口，不自行追加修复轮次。
```

## 8. 人类审批检查清单

- [ ] 当前任务范围、产物与验收已写清楚
- [ ] 本地 Agent 的检查确实执行，未运行部分明确标注
- [ ] 审核者区分自己验证和他人报告
- [ ] PR 是否合并：**只有我明确批准才执行**
- [ ] 是否制作安装包：**另行确认版本、依赖、许可证与校验值**
- [ ] 是否公开发布：**另行批准公开受众与目标位置，并测试匿名访问**

这套模板可以用于开发、文档、数据处理等任务；不表示每次都需要 GitHub PR 或软件打包。
